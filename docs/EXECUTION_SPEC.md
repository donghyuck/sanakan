# 이슈 기반 자동화 코딩 실행 명세

## 제품 목표

GitLab 이슈 등록 → 메인 에이전트 계획 → 개발 → 필수 검증 → 독립 AI 리뷰 →
필요한 수정 반복 → Draft MR 생성 및 사람 리뷰 요청을 여러 프로젝트에 적용한다.
Sanakan은 이 절차를 실행하는 도구이며 가이드와 플러그인은 도구의 설정·배포 수단이다.

## 적용 순서

먼저 [기존 로컬 Git 프로젝트](INSTALL_LOCAL.md)에서 작업 JSON과 실제 Codex로 개발·검증·리뷰를 실증한다.
로컬 fixture 실행의 완료 기준은 ready와 검토 가능한 patch이며 GitLab/토큰/MR은 필요 없다.
그다음 실제 GitLab 이슈와 게시기를 연결한다. 로컬 fixture 결과를 원격 게시 결과로 간주하지 않는다.

## 1.5.0: 주기적 감시와 Codex 관리

[자동화 운영 가이드](AUTOMATION.md)의 develop/publish 감시기가 이슈 수신부터 MR 게시를 연결한다.
브랜치·커밋·MR 형식 정책, 중지·재시도·재시작 상태 복구와 Codex 관리 스킬을 제공한다.
기존 단일 이슈 실행도 유지한다. 실제 Codex 로컬 실증은 수행했고 Docker/GitLab 실증은 미수행이다.
운영 경계는 [격리와 전달 계약](EXECUTION_BOUNDARY.md)을 따른다.

## 단일 작업 실행 계약

- 프로젝트 하나, 지정된 이슈 작성자, 고정 baseline, 정확한 수정 경로 목록.
- 보호된 설정의 유효 기간·필수 검증·최종 리뷰어 ID를 사용한다.
- 메인 세션은 코드 영향과 구현/질문/승인 필요 여부를 판단한다.
- 개발 세션은 승인 범위에서 구현하며, 리뷰 세션은 별도 checkout에서 같은 patch를 읽는다.
- 세션 간 전달 자료와 다음 역할 실행은 Python 조정기가 관리한다.
  메인 세션 내부에서 다른 세션을 직접 spawn하는 방식은 아니다.
- 실패 피드백을 메인에 돌려보낸 후 최대 5회 안에서 재계획/수정한다.
- 필수 검증은 실제 프로세스 종료 코드와 보호된 명령 목록으로 판정한다.
- 게시기는 동일 issue revision, baseline, patch digest, remote tree를 확인한다.
- GitLab Commits API로 작업 branch와 commit을 만들고 MR API로 Draft MR/reviewer를 설정한다.
  Git push 프로세스를 사용하지 않으며 force/자동 병합을 제공하지 않는다.

## 실행 상태

`starting → planning → implementing → collecting → verifying → reviewing → ready`

- 테스트/리뷰 실패: 다음 attempt의 planning으로 복귀.
- 정보 부족·고위험·개발 차단·수정 한도 도달: `needs_human`.
- schema 오류·범위 위반·timeout·명령 실패: `failed`.
- 별도 게시 단계: `ready → publishing → published`.
- 게시 중 통신 실패: `publishing`을 유지하고 재실행 시 remote 상태부터 조회.

같은 프로젝트/이슈를 하나의 POSIX 파일 잠금으로 직렬화한다.
같은 입력으로 다시 run하면 기존 상태를 반환하며 모델을 다시 실행하지 않는다.
이슈나 설정이 바뀌면 기존 결과를 덮어쓰지 않고 중단한다.
중단된 개발의 자동 재개와 이슈 답변/댓글 처리는 후속 버전 범위다.

## 완료 조건

1. 로컬 fixture에서 계획·개발·검증·독립 리뷰와 수정 반복이 재현된다.
2. 같은 이슈의 반복 실행으로 중복 개발/MR이 생기지 않는다.
3. 실패/질문/범위 이탈/오래된 이슈/이동한 target branch는 게시되지 않는다.
4. MR 생성 응답이 유실돼도 기존 branch/MR을 조회해 재개한다.
5. 게시 결과의 파일 tree, baseline 부모, reviewer, Draft 상태를 다시 확인한다.
6. 실제 GitLab 시범 프로젝트에서 동일 흐름을 검증한다. **아직 미수행.**

## 이후 단계

1. 기존 로컬 Git 프로젝트에서 실제 모델로 작은 작업을 실증한 뒤 GitLab 프로젝트·리뷰 담당자를 연결.
2. Webhook 수신·발신 검증·큐·작업 취소·배포 환경 전체 잠금 도입.
3. 사람의 질문 답변/리뷰 댓글을 받아 기존 작업을 재개하는 흐름.
4. 비용 예산·로그 크기 제한·운영 관측·장애 복구 강화.
5. 제공된 Sanakan CLI 관리 플러그인의 실제 설치·사용 실증 및 필요 시 MCP 추가.

## 운영 경계

현재 구현은 POSIX 단일 호스트 파일럿이다. CLI sandbox와 별도 clone은 컨테이너/VM 격리의 대체물이 아니다.
검증 명령은 프로젝트 코드를 실행한다. 실제 운영에서는 별도 OS 계정/컨테이너·네트워크 제한과
호스트가 관리하는 쓰기 불가 정책/결과 저장소를 준비해야 한다. 같은 UID가 모든 디렉터리를
수정할 수 있는 환경에서 파일 digest만으로 검증 증거의 진위를 보장하지 않는다.
작성자 allowlist는 사전 승인된 프로젝트 정책의 일부이며 이슈 본문 자체를 승인으로 해석하지 않는다.
