# Backend 개발 규칙

- 프로젝트의 기존 계층 구조를 유지한다.
- Controller에 업무 로직을 직접 넣지 않는다.
- Service의 트랜잭션 경계를 확인한다.
- Repository, Mapper, JPA 사용 방식을 혼합 변경하지 않는다.
- 공통 응답·예외·오류 코드를 유지한다.
- 인증 사용자 식별을 요청 파라미터만으로 판단하지 않는다.
- 다른 사용자 데이터 접근 가능성을 검증한다.
- SQL 변경은 성능, 정렬, 페이징, Null, 중복을 확인한다.

## PM 승인 없이는 금지

- 테이블·컬럼·인덱스
- DDL·마이그레이션
- 인증·권한 구조
- API 계약
- 신규 운영 의존성
- 운영 설정

## 검증

- 정상 처리
- 잘못된 입력
- 인증 없음
- 권한 없음
- 데이터 없음
- 중복 요청
- 예외와 트랜잭션
- 관련 단위·통합 테스트
