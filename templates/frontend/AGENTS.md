# Frontend 개발 규칙

- 기존 컴포넌트 구조와 상태관리 패턴을 유지한다.
- 기존 API Client와 인증 인터셉터를 사용한다.
- 컴포넌트별 별도 HTTP Client를 만들지 않는다.
- API URL과 권한값을 하드코딩하지 않는다.
- 화면에서 버튼을 숨기는 것만으로 권한 검증을 완료했다고 판단하지 않는다.
- 로딩, 빈 데이터, 오류, 권한 없음, 세션 만료 상태를 처리한다.
- 중복 클릭과 중복 요청을 방지한다.
- 요구사항과 무관한 디자인 변경을 하지 않는다.

## PM 승인 없이는 금지

- 공통 레이아웃 대규모 변경
- 인증·라우터 권한 구조
- 공통 API 계약
- 신규 UI 프레임워크
- 핵심 라이브러리 버전

## 검증

- lint
- typecheck
- test
- build
- 정상·빈 데이터
- API 오류
- 권한 없음
- 세션 만료
- 재진입
- 반응형 또는 지원 해상도
